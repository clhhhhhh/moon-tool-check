# 工具链契约对照实验

从仓库根目录运行 `moon build --target js`，安装 Python 的 `jsonschema`，再运行 `python examples/evaluate.py`。用例由脚本和仓库里的 JSON 样例生成。原始数据见 [results.json](results.json)。

## 实验设计

每条订单、知识库和报表工作流各有四种升级。故障升级分别是订单编号变为可空、知识库允许返回空数组、报表计数上限由 100 提高到 101。三个正常升级分别改描述、改格式、增加当前工作流未绑定的输出字段。

另外两个有限域用例检查同源相关性。下游同时读取同一个上游对象的字段 a 和 b，只接受两个布尔值相等的输入。升级一增加可接受的同时为真的响应。升级二再增加一真一假的响应，实际触发故障。实验脚本穷举合法的上游响应，用独立验证器确定预期结果。

## 结果

| 方法 | 检出工作流故障 | 正常工作流被标记 |
| --- | ---: | ---: |
| 文本差异 | 4/4 | 10/10 |
| 工具 Schema 结构差异 | 4/4 | 4/10 |
| 工具级语义兼容检查 | 4/4 | 4/10 |
| MoonToolCheck 工作流绑定检查 | 4/4 | 0/10 |

工具级语义基线使用项目的 catalog-diff 命令，判断新工具的输入和输出能否满足旧工具的完整契约。表中的「正常工作流被标记」以当前工作流能否执行为口径。工具级检查发现的四处契约变化，对其他调用者仍可能有影响。

所有四份反例均由 Python Draft 2020-12 验证器复核。脚本先确认上游响应合法，再按实际绑定独立重建下游请求，最后确认下游拒绝该请求。工作流检查无无法判定的用例。

每个用例启动 CLI 五次并记录墙钟时间中位数。该时间包含 Node.js 启动和文件读取。结果适用于这 14 个定向构造的用例。
